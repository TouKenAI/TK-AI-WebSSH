## 1. 代码规范

### 1.1 Python代码规范

**遵循**：PEP 8 + Google Python Style Guide

**关键规则**：

1. **函数长度**：不超过50行（AI可维护）
2. **文件长度**：不超过300行（AI可维护）
3. **命名**：
   - 函数/方法：snake_case（小写+下划线）
   - 类名：PascalCase（首字母大写）
   - 常量：UPPER_CASE（全大写+下划线）
   - 私有函数：_leading_underscore（单下划线前缀）
4. **注释**：
   - 每个函数必须有docstring（解释"为什么"，不是"做什么"）
   - 复杂逻辑必须有行内注释
5. **错误处理**：
   - 不要静默失败（silent failure）
   - 记录详细错误信息（包含上下文）
   - 返回友好的用户提示

**示例**：

```python
# ✅ 好：清晰、简洁、有docstring
def generate_command(user_input, device_type="linux"):
    """
    生成SSH命令（调用阶跃星辰API）
    
    Args:
        user_input: 用户自然语言输入
        device_type: 设备类型（linux/huawei_vrp/cisco_ios）
    
    Returns:
        {
            "command": "df -h",
            "description": "查看磁盘使用情况",
            "risk_level": "safe"
        }
    
    Raises:
        ValueError: AI返回格式错误
        requests.HTTPError: API调用失败
    """
    try:
        system_prompt = get_system_prompt(device_type)
        messages = [
            {"role": "system", "content": system_prompt},
            {"role": "user", "content": user_input}
        ]
        
        response = requests.post(
            STEPFUN_API_URL,
            headers={"Authorization": f"Bearer {STEPFUN_API_KEY}"},
            json={
                "model": "step-3.5-flash-2603",
                "messages": messages,
                "response_format": {"type": "json_object"}
            },
            timeout=30
        )
        response.raise_for_status()
        
        result = response.json()["choices"][0]["message"]["content"]
        command_info = json.loads(result)
        
        if "command" not in command_info:
            raise ValueError("AI返回格式错误：缺少command字段")
        
        return command_info
        
    except requests.HTTPError as e:
        logger.error(f"阶跃星辰API返回错误: {e.response.status_code} {e.response.text}")
        return {"error": f"AI API返回错误: {e.response.status_code}"}
    except Exception as e:
        logger.error(f"调用阶跃星辰API时发生未知错误: {str(e)}")
        return {"error": f"发生未知错误: {str(e)}"}

# ❌ 差：函数名不清淅、没有注释、错误处理不当
def proc(data):
    r = requests.post(url, json=data)
    return r.json()
```

### 1.2 JavaScript代码规范

**遵循**：Airbnb JavaScript Style Guide

**关键规则**：

1. **变量声明**：用`const`，不用`var`
2. **函数定义**：用箭头函数（Arrow Function）
3. **异步操作**：用`async/await`，不用回调函数
4. **错误处理**：`try/catch`包裹异步操作
5. **命名**：
   - 变量/函数：camelCase（首单词小写）
   - 类名：PascalCase（首字母大写）
   - 常量：UPPER_CASE（全大写+下划线）

**示例**：

```javascript
// ✅ 好：清晰、简洁、有错误处理
const generateCommand = async (userInput, deviceType = 'linux') => {
  try {
    const response = await fetch('/api/ai/chat', {
      method: 'POST',
      headers: { 'Content-Type': 'application/json' },
      body: JSON.stringify({ message: userInput, device_type: deviceType })
    });
    
    if (!response.ok) {
      throw new Error(`HTTP error! status: ${response.status}`);
    }
    
    const data = await response.json();
    return data;
  } catch (error) {
    console.error('生成命令时发生错误:', error);
    return { error: error.message };
  }
};

// ❌ 差：没有错误处理、命名不清淅
function proc(data) {
  fetch('/api/ai/chat', { method: 'POST', body: data })
    .then(res => res.json())
    .then(data => console.log(data));
}
```

## 2. API规范

### 2.1 REST API规范

**遵循**：OpenAPI 3.0 规范

**关键规则**：

1. **URL格式**：`/api/{资源名}/{操作}`
   - 正确：`/api/devices/list`
   - 错误：`/api/getDeviceList`

2. **HTTP方法**：
   - GET：查询
   - POST：创建/执行
   - PUT：更新
   - DELETE：删除

3. **响应格式**：统一格式

```json
{
  "success": true,
  "data": { ... },
  "error": null
}
```

4. **错误响应格式**：

```json
{
  "success": false,
  "data": null,
  "error": "错误描述"
}
```

5. **状态码**：
   - 200：成功
   - 400：请求格式错误
   - 401：未认证
   - 403：无权限
   - 500：服务器内部错误

## 3. 数据库规范

### 3.1 SQLite规范

**关键规则**：

1. **表名**：复数形式，snake_case
   - 正确：`users`, `audit_logs`
   - 错误：`user`, `auditLog`

2. **字段名**：snake_case
   - 正确：`created_at`, `user_id`
   - 错误：`createdAt`, `userId`

3. **主键**：`id INTEGER PRIMARY KEY AUTOINCREMENT`

4. **外键**：明确声明`FOREIGN KEY`

5. **索引**：常用查询字段加索引

**示例**：

```sql
-- ✅ 好：清晰的表结构
CREATE TABLE users (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    username TEXT UNIQUE NOT NULL,
    password_hash TEXT NOT NULL,
    role TEXT DEFAULT 'user',
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP
);

CREATE INDEX idx_users_username ON users(username);

-- ❌ 差：字段名不清晰
CREATE TABLE user (
    id INT PRIMARY KEY,
    name TEXT,
    pwd TEXT
);
```

## 4. Git规范

### 4.1 分支管理

| 分支 | 用途 | 保护规则 |
|------|------|---------|
| `main` | 生产环境 | 不允许直接提交，必须PR |
| `dev` | 开发环境 | 可以直接提交 |
| `feature/*` | 新功能 | 完成后合并到`dev` |
| `hotfix/*` | 紧急修复 | 完成后合并到`main`和`dev` |

### 4.2 Commit Message规范

**格式**：`<type>: <subject>`

**type类型**：

- `feat`：新功能
- `fix`：修复bug
- `docs`：文档变更
- `style`：代码格式（不影响功能）
- `refactor`：重构（不是新功能，也不是修复）
- `perf`：性能优化
- `test`：测试相关
- `chore`：构建过程或辅助工具的变动

**示例**：

```
feat: 添加AI对话侧边栏
fix: 修复危险命令拦截逻辑
docs: 更新架构规划书v7
```

```python
def test_validate_command_safe():
    """测试安全命令验证"""
    command_info = {"command": "df -h", "description": "查看磁盘"}
    is_valid, error = validate_command(command_info)
    assert is_valid == True
    assert error == ""

def test_validate_command_danger():
    """测试危险命令验证"""
    command_info = {"command": "rm -rf /", "description": "删除所有文件"}

    assert is_valid == False
    assert "危险命令" in error
```

## 7. 安全规范

### 7.1 敏感信息处理

**规则**：

1. **禁止硬编码**：API Key、密码等敏感信息禁止硬编码
2. **使用环境变量**：敏感信息通过环境变量传入
3. **.gitignore**：`.env`文件必须加入`.gitignore`
4. **日志脱敏**：日志中不能出现密码、API Key等敏感信息

**示例**：

```python
# ✅ 好：从环境变量读取
import os
STEPFUN_<SECRET_REDACTED>"STEPFUN_API_KEY}")

# ❌ 差：硬编码
STEPFUN_<SECRET_REDACTED>
```

### 7.2 命令安全

**规则**：

1. 危险命令必须拦截
2. 命令执行前必须验证
3. 命令结果必须记录
