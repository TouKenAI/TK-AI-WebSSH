## 2. 开发环境部署

### 2.1 快速启动（5分钟）

**步骤**：

1. 克隆项目（如果还没有）：

```bash
git clone https://github.com/bifrost0x/webssh.git tkai-ssh
cd tkai-ssh
```

2. 创建虚拟环境：

```bash
python -m venv venv
source venv/bin/activate  # Linux/Mac
# 或
venv\Scripts\activate  # Windows
```

3. 安装依赖：

```bash
pip install -r requirements.txt
```

4. 配置API Key（按用户要求，保留明文方便测试）：

**方式1：直接修改config.yaml**

```yaml
# config.yaml
ai:
  stepfun:
    <SECRET_REDACTED>
```

**方式2：环境变量**（推荐，生产环境用这个）

```bash
export STEPFUN_API_KEY="your-stepfun-api-key-here"
```

5. 运行项目：

```bash
python app.py
```

6. 访问：`http://localhost:5000`

### 2.2 开发环境配置建议

| 配置项 | 建议值 | 说明 |
|--------|--------|------|
| DEBUG | True | 开启调试模式 |
| LOG_LEVEL | DEBUG | 详细日志 |
| DATABASE | SQLite（本地文件） | 轻量，方便测试 |

## 3. 生产环境部署

### 3.1 部署架构

```
用户浏览器
    ↓ HTTPS (可选)
Nginx (反向代理)
    ↓ HTTP
Flask (gunicorn多进程)
    ↓
SQLite / 文件系统
```

### 3.2 部署步骤（Linux服务器）

**步骤1：安装依赖**

```bash
# Ubuntu/Debian
sudo apt update
sudo apt install -y python3.13 python3-pip nginx

# CentOS/RHEL
sudo yum install -y python313 python3-pip nginx
```

**步骤2：部署代码**

```bash
# 假设代码在 /opt/tkai-ssh
sudo mkdir -p /opt/tkai-ssh
sudo cp -r . /opt/tkai-ssh/
cd /opt/tkai-ssh

# 安装Python依赖
pip3 install -r requirements.txt
```

**步骤3：配置环境变量（生产环境必须用这个）**

```bash
# 创建 .env 文件
cat > /opt/tkai-ssh/.env << EOF
STEPFUN_<SECRET_REDACTED>
FLASK_SECRET_KEY=your-secret-key-here
EOF

# 设置权限（只有owner能读）
chmod 600 /opt/tkai-ssh/.env
```

**步骤4：配置systemd服务**

创建`/etc/systemd/system/tkai-ssh.service`：

```ini
[Unit]
Description=TKAI SSH Service
After=network.target

[Service]
Type=notify
User=www-data
Group=www-data
WorkingDirectory=/opt/tkai-ssh
Environment="PATH=/opt/tkai-ssh/venv/bin"
ExecStart=/opt/tkai-ssh/venv/bin/gunicorn -w 4 -b 127.0.0.1:5000 app:app
Restart=always

[Install]
WantedBy=multi-user.target
```

启动服务：

```bash
sudo systemctl daemon-reload
sudo systemctl enable tkai-ssh
sudo systemctl start tkai-ssh
```

**步骤5：配置Nginx反向代理**

创建`/etc/nginx/sites-available/tkai-ssh`：

```nginx
server {
    listen 80;
    server_name your-domain.com;

    location / {
        proxy_pass <INTERNAL_URL_REMOVED>
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }

    location /ws/ {
        proxy_pass <INTERNAL_URL_REMOVED>
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
    }
}
```

启用配置：

```bash
sudo ln -s /etc/nginx/sites-available/tkai-ssh /etc/nginx/sites-enabled/
sudo nginx -t
sudo systemctl restart nginx
```

## 4. Docker部署

### 4.1 Dockerfile

```dockerfile
FROM python:3.13-slim

WORKDIR /app

# 安装依赖
COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt

# 复制代码
COPY . .

# 暴露端口
EXPOSE 5000

# 启动命令
CMD ["gunicorn", "-w", "4", "-b", "0.0.0.0:5000", "app:app"]
```

### 4.2 Docker Compose

**docker-compose.yml**：

```yaml
version: '3.8'

services:
  tkai-ssh:
    build: .
    ports:
      - "5000:5000"
    environment:
      - STEPFUN_<SECRET_REDACTED>
      - FLASK_SECRET_KEY=${FLASK_SECRET_KEY}
    volumes:
      - ./data:/app/data
    restart: unless-stopped
```

**启动**：

```bash
docker-compose up -d
```

## 5. 纯内网环境部署

### 5.1 场景说明

**需求**：客户环境纯内网，不能访问互联网，但需要AI功能。

**方案**：

1. **阶跃星辰API**：如果内网能访问互联网（通过代理），则直接用
2. **本地模型**：如果完全不能访问互联网，则部署Ollama本地模型

### 5.2 离线部署步骤

**步骤1：在外网机器下载依赖**

```bash
# 下载Python依赖包
pip download -r requirements.txt -d ./packages

# 打包代码和依赖
tar -czf tkai-ssh-offline.tar.gz tkai-ssh/ packages/
```

**步骤2：拷贝到内网机器**

```bash
# 用U盘或内网文件服务器拷贝
scp tkai-ssh-offline.tar.gz user@internal-server:/opt/
```

**步骤3：在内网机器安装**

```bash
# 解压
tar -xzf tkai-ssh-offline.tar.gz -C /opt/

# 安装依赖（离线）
pip install --no-index --find-links=/opt/packages -r /opt/tkai-ssh/requirements.txt

# 配置本地模型（Ollama）
# 参考Ollama官方文档
```

## 7. 常见问题排查

### 7.1 SSH连接失败

**症状**：Web终端连不上服务器

**排查步骤**：

1. 检查目标服务器IP和端口是否正确
2. 检查用户名和密码/密钥是否正确
3. 检查网络连通性（ping目标服务器）
4. 检查防火墙规则

**解决**：

```bash
# 测试SSH连接（命令行）
ssh user@ip -p port

# 如果命令行能连，但Web终端不能连，检查paramiko日志
tail -f data/logs/tkai_ssh.log
```

### 7.2 AI API调用失败

**症状**：AI对话返回错误

**排查步骤**：

1. 检查API Key是否正确
2. 检查API地址是否正确（https://api.stepfun.com/step_plan/v1）
3. 检查网络是否能访问阶跃星辰API
4. 检查API配额是否用完

**解决**：

```bash
# 测试API可达性
curl -X POST https://api.stepfun.com/step_plan/v1/chat/completions \
  -H "<SECRET_REDACTED> your-api-key" \
  -H "Content-Type: application/json" \
  -d '{"model":"step-3.5-flash-2603","messages":[{"role":"user","content":"你好"}]}'
```

### 7.3 命令执行超时

**症状**：执行命令长时间无响应

**排查步骤**：

1. 检查命令是否需要交互输入（如`vim`）
2. 检查命令是否死循环
3. 检查网络延迟

**解决**：

- 在`config.yaml`中增加超时时间：

```yaml
ssh:
  timeout: 60  # 秒
```

## 8. 性能调优

### 8.1 Flask优化

| 优化项 | 建议 | 说明 |
|--------|------|------|
| 使用gunicorn | `gunicorn -w 4` | 多进程，提高并发 |
| 启用gzip | Nginx配置 | 减少传输数据量 |
| 静态资源CDN | 可选 | 加快页面加载 |

### 8.2 数据库优化

| 优化项 | 建议 | 说明 |
|--------|------|------|
| 加索引 | 常用查询字段 | 加快查询速度 |
| 定期清理日志 | 保留最近3个月 | 减少数据库大小 |
| 使用连接池 | SQLAlchemy | 减少连接开销 |

## 9. 备份与恢复

### 9.1 备份内容

| 内容 | 路径 | 备份频率 |
|------|------|---------|
| 数据库 | `data/tkai_ssh.db` | 每天 |
| 审计日志 | `data/logs/audit.log` | 每天 |
| 配置文件 | `config.yaml` | 每次修改后 |

### 9.2 备份脚本

```bash
#!/bin/bash
# backup.sh

BACKUP_DIR="/opt/backups/tkai-ssh"
DATE=$(date +%Y%m%d)

mkdir -p $BACKUP_DIR

# 备份数据库
cp data/tkai_ssh.db $BACKUP_DIR/tkai_ssh_$DATE.db

# 备份审计日志
cp data/logs/audit.log $BACKUP_DIR/audit_$DATE.log

# 备份配置文件
cp config.yaml $BACKUP_DIR/config_$DATE.yaml

# 删除7天前的备份
find $BACKUP_DIR -name "*.db" -mtime +7 -delete
find $BACKUP_DIR -name "*.log" -mtime +7 -delete
find $BACKUP_DIR -name "*.yaml" -mtime +7 -delete
```

**定时执行**（crontab）：

```bash
0 2 * * * /opt/tkai-ssh/backup.sh
```
